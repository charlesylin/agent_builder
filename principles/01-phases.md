id: phases
title: Phase control
---
Work proceeds through **Define → Plan → Build → Review**. A phase changes only when the project
author explicitly invokes or approves the next phase. An agent must not infer a transition from
conversational momentum. Read `governance/project-state.yaml` before substantive work and
operate only within its current phase.

1. **Define:** establish the outcome, owner, users, scope, non-goals, authority, risks, and
   initial success signals. Do not select or implement a runtime.
2. **Plan:** research established open-source options, design contracts and failure behavior,
   record substantive decisions, and obtain approval before implementation.
3. **Build:** implement only the approved plan in small, testable increments.
4. **Review:** exercise the result with realistic work, capture author feedback, and turn the
   experience into acceptance criteria and the next iteration.

## Short form

Operate only in the phase recorded in `governance/project-state.yaml` — Define, Plan, Build, or
Review. Transition only with explicit project-author approval; never infer one from discussion.
