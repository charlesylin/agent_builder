title: Search before building
---
During Plan, before proposing Build, search for an existing public solution that satisfies the
actual need. Check a user-provided codebase too when one is offered; do not assume a particular
organization or repository. In `planning/solution-evaluation.md`, name sources and candidates,
and assess fit, utilization, maintenance, tests, security history, licensing, and setup burden.
Compare adoption, adaptation, and a custom build with an evidence-backed recommendation. A
public solution that suffices should be recommended for adoption, not treated as inspiration
for an unnecessary custom project. After the author confirms adoption, record its version and
archive the project in Plan without entering Build or inventing a project release. If work
continues, explain why no suitable candidate fully meets the version-sized need.

## Short form

Require a build-or-adopt decision before Build. Recommend a suitable public solution and
archive after author confirmation; otherwise explain the evidence for adapting or building.
