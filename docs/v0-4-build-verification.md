# v0.4.0 Build verification

Checkpoint: 2026-10-05. The scoped Build implementation is mechanically complete.
The author closed Build and opened Review on 2026-10-06. This is **not** acceptance
or a release tag.

## What was built

- A filtered Spec Kit v1.1.0 bundle generated by its CLI from commit
  `f1d3a4f8337ebbd3ae22760a9c12e3352b93a175` (MIT). It contains seven selected
  instruction files for each of Claude Code and Codex, six Bash helpers, four project
  templates, hashes, generation provenance, and the license. No Spec Kit CLI is installed
  or invoked on member machines.
- New v0.4.0 `agent`, `skill`, and `project` seeds for those hosts contain the helper and
  template subset, a checked copy of the Agent Builder operating agreement, and a pin
  marker. Existing seeds remain unchanged. Gemini-only seeding retains the prior path.
- The Agent Builder skill routes early Plan research through the bundled
  `assess-research` instructions, keeps the final adopt/adapt/build decision in Agent
  Builder, and uses selected Spec Kit specification and planning instructions only for
  an approved build. The checker requires the research artifact and, on the build path,
  a feature spec, plan, and tasks before Plan can close.

## Verification performed

- First-slice live handoff in disposable projects: authenticated Claude Code and Codex
  each used Agent Builder as the sole invoked skill, read the selected host-specific
  upstream research instructions, and wrote the expected
  `.specify/assessments/<slug>/research.md` artifact. The examples had a substantive
  problem statement, not only a slug. Neither host changed the phase or decided
  adoption on its own. This passed the approved stop/go handoff gate.
- Public-source verification did **not** pass in those pilot environments: Codex's
  inner sandbox had no public DNS/network access, and Claude Code's web tools were
  unavailable to that run. Both artifacts marked candidate claims as assumptions and
  overall confidence as low. A real sourced adopt recommendation is a required Review
  control, not something this Build claims to have demonstrated.
- A copied, self-contained Agent Builder skill seeded all six host/kind combinations
  without a Spec Kit CLI or download. The generated projects validated; no excluded
  `implement` or `converge` skill was installed. A fresh Codex project ran the bundled
  feature, plan, and prerequisites helpers and validated afterward.
- `python3 -m unittest discover -s tests -q`: 74 passed on Python 3.14.0.
  `/usr/bin/python3 -m unittest discover -s tests -q`: 74 passed on Python 3.9.6.
  `ruff check .`, `ruff format --check .`, `scripts/render.py --check`,
  `scripts/refresh_spec_kit.py --check`, compilation, and `git diff --check` passed.
- `check.py . --leaving build` reports no unresolved decisions. Its generic scaffold
  check is deliberately inapplicable to this legacy source repository, which has no
  `.agent-builder.json` and contains unrendered templates; generated projects pass it.

## Still to test in Review

Run the installed v0.4.0 Agent Builder in **separate test projects**. First ask its version:
the plugin and the new project's `.agent-builder.json` should report `0.4.0`, and
`.specify/spec-kit-provenance.json` should report upstream `1.1.0` at the commit above.
In Plan, before the final build-or-adopt decision, it should create and link a sourced
research artifact. Test both a suitable-public-solution adoption and a justified small
build, including a contradiction that `analyze` should surface. The controls and
authority boundaries are in `planning/v0-4-implementation-plan.md`. Send the test
project path or repository and a short account of what happened for inspection.

The pilot was not a full organization-plugin installation or a real-use adoption/build
session. Those outcomes, and whether the extra steps improve rather than burden the
v0.3.0 experience, remain open until Review.
